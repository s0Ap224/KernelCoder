# E2B 接入计划（暂存）

记录日期：2026-10-15。

状态：2026-10-16 已实现最小闭环并通过真实 E2B 验收。下文保留最初设计记录；当前操作、限制与恢复流程见 [沙箱指南](../sandbox/README.md)。

## 数据与职责

- 原项目：只有用户显式触发的 apply 才写回。
- 本地 workspace.tree：文件工具操作的副本，也是审查和恢复的本地项目状态。
- E2B /workspace：Bash 命令执行的远程项目副本。
- baseline、meta.json、审查候选、检查点、备份和日志保留在宿主，不上传。

## 执行流程

1. 沿用 SandboxWorkspace.create 建立副本、基线和文件指纹。
2. 第一次需要 Bash 时创建 E2B 沙箱，记录沙箱 ID；当前会话内复用。
3. 每次执行前，在工作区保护范围内校验并同步本地 tree 的新增、修改和删除。用同步清单区分项目文件与远程依赖、缓存，不清空整个沙箱。
4. 将 cwd 映射并限制到远程工作区。记录活动标记，执行命令，收集退出码与有界输出。
5. 确认命令及相关写入进程停止后，枚举远程变化，下载到本地临时区。校验相对路径、文件类型、链接、大小和数量，再更新 tree，包含删除。非零退出码也需处理文件变化。
6. 同步失败时保留可恢复状态，阻止继续执行和写回，避免把部分下载当作完整结果。
7. 返回统一 ExecutionResult，供 BashTool 渲染。
8. 沿用 review 冻结候选，以及用户显式触发 apply 的冲突校验、备份和恢复流程。

## 超时、取消与生命周期

- 命令超时与沙箱存活时间分别配置。
- SDK 连接超时不等于远程执行停止；必须显式终止并确认，无法确认时保留活动标记。
- 第一版限制后台常驻任务，需要设计进程及子进程的停止确认。
- 正常退出先同步，再销毁远程沙箱；本地工作区和审查记录保留。
- 下次恢复可新建环境并从 tree 重建；临时安装的依赖需重新安装，后续可用模板优化。
- 异常退出、沙箱创建后未成功记录 ID、下载与本地提交中断等恢复窗口，需在详细设计中处理。

## 用户准备与待定项

- E2B 账号、可用额度、本机访问 E2B 的网络。
- 在宿主配置 E2B_API_KEY，不把密钥发到聊天或自动注入沙箱；模型 API Key 同样保留在宿主。
- 后续为 KernelCoder 添加并固定 e2b Python SDK 版本。
- 提供项目依赖文件、安装命令、测试命令和特殊系统依赖。
- 明确 Linux 兼容性、Python/Node 版本需求、私有依赖需求。
- 建议起步配置：默认环境、允许联网安装依赖、会话内复用、退出销毁；具体配置尚未实施。
