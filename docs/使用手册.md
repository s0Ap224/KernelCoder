# KernelCoder 使用手册：本地与 E2B

安装、配置各做一次。以后在要处理的项目目录打开终端，输入 `kernelcoder` 即可。

## 1. Windows 首次安装

准备 Python 3.11 或以上、Git for Windows。安装 Git 时保留 Git Bash，并允许终端使用 Git。
E2B 模式仍需在本机运行 KernelCoder 客户端；它将 Bash 命令交给云端 Linux 执行。

在 PowerShell 中依次运行：

```powershell
git clone https://github.com/s0Ap224/KernelCoder.git
cd KernelCoder
& .\scripts\install.ps1
kernelcoder --version
```

脚本创建或复用仓库内的 `.venv`，安装 KernelCoder，并把命令加入当前终端及用户 PATH。
不需要管理员权限，也不需要激活虚拟环境。重复运行不会重复添加 PATH。
其他已经打开的终端需要重新打开。仓库是可编辑安装的来源，安装后请保留其位置。

如果 PowerShell 提示脚本执行被禁，可在确认来源后仅对这次脚本进程运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

此方式安装后需重新打开终端。若存在组织策略限制，请按组织要求处理。
如果 `python` 不是正确的解释器，可传入路径：

```powershell
& .\scripts\install.ps1 -Python "C:\Python313\python.exe"
```

macOS/Linux 可使用已有 Python 3.11+ 环境执行 `python3 -m pip install -e .`，确认该环境的命令目录在 PATH 后，使用下文相同的 KernelCoder 命令。首版安装脚本面向 Windows。

## 2. 首次配置模型

```powershell
kernelcoder init
```

按提示选择默认执行模式、填写模型名称、API Base URL、模型 API Key。
Key 输入隐藏；直接按 Enter 保留已有配置。Base URL 输入 `-` 可清空，使用 SDK 默认地址。
选择 E2B 时还需填写 E2B API Key；本地模式不需要它。

模型服务需要提供 OpenAI 兼容接口。模型名称和 Base URL 按你的服务商提供的信息填写。
本地执行指工具在本机运行，模型请求仍发往所配置的服务；只有使用本地模型服务时，模型才在本机运行。

配置保存在当前用户的以下位置：

| 文件 | 用途 |
| --- | --- |
| `~/.kernelcoder/.env` | 模型、接口及 E2B 凭据 |
| `~/.kernelcoder/settings.json` | 默认执行模式、受管 MCP 设置 |
| `~/.kernelcoder/history` | 终端输入历史 |

Windows 中 `~` 通常为 `C:\Users\你的用户名`。不要将配置凭据发到聊天或提交到 Git。
再次执行 `kernelcoder init` 可修改配置，保存前显示不含密钥值的摘要并确认覆盖。

### 已经有 KernelCoder 的 .env

在 KernelCoder 仓库目录运行一次：

```powershell
kernelcoder init --from-env .\.env
```

也可以传入文件的绝对路径。导入只识别 KernelCoder 支持的配置变量，之后从其他项目启动就能使用全局配置。
导入过程会继续询问模式和模型信息；直接按 Enter 使用导入值。

## 3. 本地执行 SOP

适合想快速尝试，并希望使用本机依赖、文件和命令的用户。
工具直接操作原项目，不创建 E2B 环境，也没有副本审查写回步骤。

**一次配置：**

```powershell
kernelcoder init --mode local
kernelcoder doctor
```

**每次使用：** 在目标项目文件夹打开 PowerShell，然后运行：

```powershell
kernelcoder
```

例如从其他目录前往项目：

```powershell
cd "C:\Projects\我的项目"
kernelcoder
```

先输入“请阅读项目并说明它的用途”，再尝试“修复这个问题，并运行相关测试”。
涉及改动的工具调用会询问授权：`y` 允许一次，`a` 记住该工具授权，`n` 拒绝。
完成后用编辑器或 `git diff` 检查改动，输入 `quit` 退出。`Ctrl+C` 取消当前操作。

Windows 的本地命令通过 Git Bash 执行；命令中需要的 Python、Node 等依赖应在本机可用。
`kernelcoder doctor` 会检查 Git Bash 是否存在。

## 4. E2B 执行 SOP

适合希望将命令放进远程 Linux 环境，并在确认后才把改动写回项目的用户。
需要模型 Key、E2B Key、本机网络以及 E2B 可用额度。

**一次配置：**

```powershell
kernelcoder init --mode e2b
kernelcoder doctor
```

`doctor` 只检查本地配置和依赖，不调用模型、不创建远程沙箱。
如需验证真实连接，可运行以下命令；它会创建、测试并销毁沙箱，使用 E2B 额度：

```powershell
kernelcoder --sandbox-check
```

**每次使用：** 在目标项目目录运行 `kernelcoder`，然后发起任务。
文件工具操作本地任务副本；第一次 Bash 调用才创建 E2B 环境，命令在 `/workspace` 执行，文件变化同步回副本。
远程环境不会继承本机安装的项目依赖；需要时请让 Agent 在远程安装。
E2B 连接失败会报错，不会转为本机执行。

完成后，在 KernelCoder 对话框逐条输入：

```text
/sandbox status
/sandbox diff
/sandbox apply
quit
```

只有显式 `apply` 才写回原项目；`--yes` 不授权写回。
如果不想保留副本中的改动，使用 `/sandbox discard`，再退出。
正常退出会清理远程实例并保留本地会话记录；不要把“退出”理解成“已写回”。

### 恢复、审查与清理

启动和退出输出中会出现沙箱会话 ID、对话 ID。下列命令中的示例 ID 需替换为实际值：

```powershell
# 继续对话；已有 E2B 会话自动沿用 E2B 模式
kernelcoder --resume conversation-id

# 重新打开任务副本
kernelcoder --sandbox-session sandbox-id

# 退出后仍可审查并写回，不需要模型调用
kernelcoder --sandbox-session sandbox-id --sandbox-action diff
kernelcoder --sandbox-session sandbox-id --sandbox-action apply

# 不保留副本修改
kernelcoder --sandbox-session sandbox-id --sandbox-action discard

# 异常中断后，确认远程停止并恢复同步、清理资源
kernelcoder --sandbox-session sandbox-id --sandbox-action cleanup
```

如使用自定义 `--sandbox-store`，恢复和管理时需传入同一存储位置。
清理失败时保留会话和日志，不要手动删除活动标记；参见 [E2B 配置与恢复](../sandbox/README.md)。
E2B 使用 Linux，Windows 专用命令和依赖需要相应调整。项目副本默认排除 `.env*`、`.git`、依赖缓存等，受管理文件总量上限为 256 MiB。

## 5. 切换模式与指定配置

临时切换一次，不改变默认设置：

```powershell
kernelcoder --mode local
kernelcoder --mode e2b
kernelcoder --env-file "C:\Config\demo.env"
kernelcoder doctor --env-file "C:\Config\demo.env"
```

永久修改默认模式：重新运行 `kernelcoder init --mode local` 或 `kernelcoder init --mode e2b`。
旧的 `--sandbox unsafe` 等同于本地模式，`--sandbox e2b` 等同于 E2B；同时指定冲突的参数会报错。

配置从高到低依次为：CLI 参数、进程环境变量、`--env-file`、项目最近的 `.env`、用户全局 `.env`、内置默认值。
项目 `.env` 从当前目录向父目录寻找，找到第一个即停止；到用户主目录或文件系统根目录为止。
变量别名在每层内解析，再比较层级，例如终端中的 `OPENAI_API_KEY` 会优先于全局文件中的 `KERNELCODER_API_KEY`。

支持的变量：`KERNELCODER_MODEL`、`KERNELCODER_API_KEY`（兼容 `OPENAI_API_KEY`、`DEEPSEEK_API_KEY`）、
`KERNELCODER_BASE_URL`（兼容 `OPENAI_BASE_URL`，同层优先）、`KERNELCODER_PROVIDER`、
`KERNELCODER_MAX_TOKENS`、`KERNELCODER_TEMPERATURE`、`KERNELCODER_MAX_CONTEXT`、`E2B_API_KEY`（兼容 `E2B_KEY`）。
环境文件按字面值读取，不展开 `${变量}`。`doctor` 会显示配置来源，不显示凭据值。

## 6. 可选：Git、Semgrep MCP

模型通过 tool use 调用工具。内置工具与 MCP 工具都进入 Agent 的工具列表；区别在于 MCP 工具通过独立服务提供，需要额外运行环境。
首次安装不包含这些依赖，读写、搜索、Bash 可以直接使用。

需要时运行：

```powershell
kernelcoder setup-mcp
kernelcoder doctor --mode e2b
kernelcoder --mode e2b
```

设置命令在 `~/.kernelcoder/mcp-env` 创建独立环境，安装项目固定版本依赖，验证成功后保存 Python 路径并为新 E2B 任务启用本地 MCP。
重复运行先验证环境，不自动升级。安装失败不改已保存设置。Semgrep 等依赖的 Python/系统兼容范围可能比客户端更窄；Windows 已验证组合见 [MCP 指南](mcp-local.md)。
已有任务沿用其保存的 MCP 设置；可用 `kernelcoder --mode e2b --mcp-backend local` 显式启用。
启动后用 `/mcp` 查看状态；无需再输入 `--mcp-python` 长路径。

这里的“本地 MCP”指 Git、Semgrep 服务在本机读取任务副本，Bash 仍在 E2B。
当前受管 MCP 需要任务副本，不能搭配直接修改原项目的本地执行模式；本地模式不会自动启用它。
临时关闭受管 MCP：`kernelcoder --mode e2b --mcp-backend off`。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| `kernelcoder` 找不到 | 重新打开终端，或在仓库重新运行安装脚本；用 `Get-Command kernelcoder -All` 检查 PATH 是否指向预期安装。 |
| Python 启动商店或版本错误 | 使用安装脚本的 `-Python` 参数指定真实 Python 3.11+ 解释器。 |
| 配置看起来没有生效 | 运行 `kernelcoder doctor` 看来源；检查终端环境变量和项目父目录 `.env` 是否覆盖全局配置。 |
| 模型认证失败或模型不存在 | 核对模型名称、API 地址和对应服务商的 Key；用 `kernelcoder init` 更新。`doctor` 不验证远程认证。 |
| 本地模式缺少 Git Bash | 安装 Git for Windows，重新打开终端，再运行 `kernelcoder doctor --mode local`。 |
| E2B 缺 Key、网络错误或额度不足 | 初始化 E2B 配置，检查账号与网络，再用 `--sandbox-check` 验证真实连接。 |
| 修改完成但原项目没变 | E2B 模式先执行 `/sandbox diff`，确认后执行 `/sandbox apply`。 |
| MCP 安装失败 | 查看 MCP 指南中的已验证版本，检查 Python 与网络，重试 `kernelcoder setup-mcp`；基础功能仍可使用。 |
| E2B 异常退出后任务被锁定 | 使用对应会话的 `cleanup`；详见 E2B 恢复指南，不要手动解除活动标记。 |

## 8. 本版验证范围

自动化覆盖配置优先级、初始化、模式、离线诊断、MCP 设置及现有会话/沙箱行为。
安装脚本通过隔离的 PowerShell 场景检查环境创建、PATH 去重和失败处理，不修改测试机器的用户 PATH。

干净 Windows 用户环境的完整安装、真实模型请求和付费 E2B 全流程需在发布前单独验收；模拟测试不能代替这些结果。


## 工具权限与 Bash 审批

使用 `--permission-mode default|acceptEdits|bypass` 选择权限模式。`--yes` 等价于 bypass，显式 ask、deny 和内容风险检查仍生效。审批展示完整命令、cwd 和执行后端，可将普通命令的精确授权保存到会话或当前项目。`/permissions` 查看规则，`/permissions reset` 清除当前项目授权。旧版全局 always 授权需要重新确认。

实现流程与修改前后对比见 [Permission 与 Bash Command 审批](../doc/permission-bash.md)。
